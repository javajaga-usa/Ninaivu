Part One

Getting it running

What Ninaivu is, how to start it on your machine, and what to do in the first ten minutes.

Chapter One

What Ninaivu is

Ninaivu is a photo library that runs on one computer in your house and serves the rest of it. Nothing leaves the building, nothing is uploaded, and there is no account to keep paying for. The photographs stay in the folders you already have them in.

You point it at a folder. It reads what is there — dates, cameras, sizes — and builds a gallery the whole household can open in a browser, from a phone in the kitchen or a laptop in the next room. It never moves or renames your files to do that.

Two apps, two doors

Ninaivu runs as two separate applications at the same time, on two different addresses. This is the single most important thing to understand about it.

The family app
:5000		 What the household opens. Starts on a profile picker — tap your face to come in.
The console
:3000		 Management only, behind an admin sign-in. Profiles, visibility, library, faces, archive, cloud, activity.

The split is a security boundary, not a layout choice. The management screens are not merely hidden on port 5000 — they are not there at all. Asking for one returns “not found”, because there is genuinely nothing to find. And a session created on the family app cannot open the console even if it belongs to an administrator.

What this means for you

You can hand out the family address to everyone in the house without worrying that somebody will wander into the settings. If you also block port 3000 at the firewall, the console becomes unreachable from the network entirely while the family app carries on serving the house.

What it will and will not do to your files

  • It never writes to your photographs. Everything it generates — the index, thumbnails, profile pictures, certificates — lives in a separate state folder.
  • It never re-encodes anything. What you put in is what comes out.
  • Deleting from Ninaivu moves a file to a recycle folder inside the library rather than destroying it.
  • Rotating a photograph saves the rotation in the index. The file on disk is untouched.

Chapter Two

Starting it on Windows

Double-click start.bat in the Ninaivu folder, or from a command prompt:

start.bat C:\Photos

The first run takes a few minutes: it builds a private Python environment beside the program, installs what it needs, finds two free ports and opens your browser. Later runs start in seconds.

Windows will ask, once, whether to allow Python through the firewall. Say yes for private networks, or nobody else in the house will be able to reach it.

Face grouping is on

start.bat now switches face grouping on for you. Nothing is downloaded until you ask for it in the console — see chapter seventeen. To start without it just this once, run set NINAIVU_FACES=0 first.

Chapter Three

Starting it on a Mac or Linux

On a Mac, double-click Ninaivu.command. The first time, macOS may refuse to run a downloaded script: right-click it, choose Open, and confirm. From then on a double-click works.

From a terminal, on either system:

python launcher/start.py ~/Pictures

To let the rest of the house in, and to switch face grouping on:

python launcher/start.py ~/Pictures --faces

Ninaivu listens on every address the machine has by default, so the household can reach it with no extra flags. If you would rather keep it to this machine while you try it out, add --local-only.

Chapter Four

The first ten minutes

The very first launch has no administrator, so the console asks you to create one. That is the only account that can change anything, and the setup screen closes permanently once it exists.

Then Ninaivu starts reading the folder. Four things happen, in this order, and you can use the gallery from the first few seconds:

  1. Indexing. One walk through the folder, then several threads doing the slow part — reading each photograph, making thumbnails, computing fingerprints. Files it has seen before, unchanged, are skipped entirely, which is why the second scan is so much faster.
  2. Duplicates. Near-identical images are grouped so you can find them.
  3. Tagging. If the AI layer is available, tags and searchable descriptions are added in the background.
  4. Faces. Last, because it is the slowest and the least urgent.
Where the dates come from

Ninaivu tries, in order: the camera's own date taken, then video metadata, then a YYYY/MM/DD folder path, then a date in the filename, and only then the file's timestamp. The details panel in the viewer tells you which one it used — useful when a scanned print claims to be from last year.

While that runs, the three things worth doing are: make profiles for the household (chapter thirteen), check the default visibility suits you (chapter fifteen), and decide whether guests can browse without a profile at all.

Part Two

The family app

Everything anyone in the house needs. No settings, nothing that can break the library.

Chapter Five

Coming in: the profile picker

Opening Ninaivu lands you on a row of faces — Who's watching? Tap yours and you are in. What that costs depends on how the profile was set up:

Tap to enter
Nothing at all. Right for a shared television or the family tablet.
PIN
Four to eight digits, shown as a small lock on the tile. Good for a teenager's profile on a shared screen.
Username and password
The full form, for anyone who wants it.
Just looking
A tile that needs no profile and shows only public photographs. It can be switched off.

Administrator profiles deliberately do not appear here, and the picker refuses to let anyone in as an administrator even if asked directly. Admins sign in on the console instead.

Everyone can change their own display name, colour and picture, whatever their role. Uploaded pictures are converted to a small square image, which strips any metadata that came with them.

Chapter Six

The gallery

The gallery opens on everything you are allowed to see, newest first, grouped by day.

Four layouts

Press J for justified, M for masonry, G for a strict grid, F for a filmstrip; + and − change the size. These are a real preference — justified suits mixed orientations, masonry suits tall photographs, grid suits scanning quickly, filmstrip suits a single long roll.

The month rail

Drag the strip down the right-hand edge to jump anywhere in the library by month. It stays smooth on a hundred thousand photographs because Ninaivu works out the whole layout from one small summary rather than loading pages as you scroll.

The sidebar

Whatever the library actually contains turns up here: discovered tags, years, folders, and — if faces are on — a row of people. Clicking any of them adds a filter you can remove again. They stack, so “beach”, 2019 and a person is one click each.

Chapter Seven

Searching, and the viewer

Searching

Type anything. If the AI layer is running you will see an AI badge, and results are ranked by how well the picture matches your words — “red car at night” and “sunset over water” work as written, without anyone having tagged anything. Without it, search still covers filenames, folders and simple tags such as wide, dark and monochrome.

The viewer

Opening a photograph shows the whole thing, fitted to your screen whatever shape it is. Scroll or pinch to zoom, drag to pan, swipe or use the arrow keys to page, double-click to zoom straight to a point.

In the viewer
FFavourite this photograph (private to you)
IDetails — camera, lens, ISO, aperture, where the date came from
SFind visually similar shots — the other eleven attempts at the same photograph
RRotate. Hold Shift to go the other way
DDownload the original
KAmbient Frame — see chapter eleven
SpaceSlideshow
0Reset the zoom and position
EscClose

A rotation saved by any family member is saved for the whole household. The file on disk is never modified.

The in-app shortcut list has two mistakes

Press ? in the app for its own list. It offers U for uploading and M for the map; neither is true. M switches to the masonry layout, and both uploading and the map have buttons of their own.

Live photographs and motion photos play their short clip automatically — Ninaivu pairs the still and the video while indexing, and also finds motion photos hidden inside a single file.

Chapter Eight

People

If face grouping is switched on, a People row appears in the sidebar, showing a face and a name. Click one and the gallery narrows to that person.

Two things about it are deliberate and worth knowing:

  • The counts are yours. The number beside a person is how many photographs you are allowed to open. Two people in the same house will see different numbers for the same person, and neither can work anything out from the difference.
  • You cannot name anyone from here. Naming people and confirming matches happen on the console. In the gallery, People is something you read, not something you change.

Very small faces — a distant face in a crowd shot — are skipped on purpose. That is the trade that keeps the ones you do see reliable.

Chapter Nine

Choosing several things at once

Click the circle on a tile to select it, hold Shift and click for a range, or use Select all on any day heading. With things selected you can favourite them in one go, or download them. An administrator also gets the visibility controls here, which is by far the quickest way to move a whole afternoon out of the family's view.

Chapter Ten

On a phone or tablet

Open the family address in the phone's browser, then use Add to Home Screen. Ninaivu supplies a proper name and icon, so it lands beside your other apps and opens without browser chrome.

Everything works by touch: pinch to zoom, drag to pan, swipe to page, long-press to select.

If typing the address is a nuisance, chapter twenty-two explains how to give the machine a name like ninaivu.local so nobody has to remember numbers.

Adding photographs from a phone

Family members and administrators can upload straight from the gallery. Files land in a folder called Uploads inside the library — or inside your own folder, if you have been given one. A name that already exists gets a timestamp rather than overwriting anything, and the new photograph appears immediately rather than waiting for the next scan.

Chapter Eleven

The Ambient Frame

Press K in the viewer. Ninaivu goes full screen, fades away every control, drifts slowly across each photograph, puts a clock in the corner and changes picture every eight seconds. Click anywhere, or press Esc, to come back.

It is the reason to keep an old tablet propped up in the kitchen. Space gives a plainer slideshow if you would rather keep the controls.

Favourites are per person: one child starring a photograph does not put it in anyone else's favourites, even when they share the same folder.

Disabling versus deleting

Disable is reversible — the profile stays, keeps its favourites, and can be switched back on. Delete is final: the profile, its favourites, its picture and any open sessions all go. Neither touches a single photograph; the library is shared, and what is being removed is only who may look at it.

You cannot delete the profile you are signed in with, and Ninaivu will not let you delete the last working administrator.

Signing somebody out everywhere

Disabling a profile, resetting its password or signing it out ends every session it has, on every device, at once. Useful when a phone goes missing.

Chapter Fourteen

Library folders, one per person

Ninaivu can index several library folders — add as many as you like on the Library tab. Each person is then given one of them, or any folder inside one.

GivenWhat they see
All library foldersEverything indexed. This is the default.
D:\PhotosThat whole library folder.
D:\Photos\2024\SummerJust that part of it.

One folder can be shared by any number of people — the family holiday album is the normal case — and sharing it shares nothing personal, because favourites stay private to each person.

Folder assignment and visibility stack, and the narrower one always wins. A guest given D:\Photos still sees only the public items inside it. Administrators are never confined. A profile pointed at a folder you later remove sees nothing at all, rather than quietly falling back to the whole library.

The console's What each role sees panel works the assignment out exactly the way a real request does, so you can check somebody before handing out a login.

Chapter Fifteen

Deciding who can see what

Every photograph sits at one of three levels.

PublicEveryone, guests included.
FamilyFamily members and administrators. This is the default for everything new, so nothing ever reaches a guest by accident.
HiddenAdministrators only. Absent from everyone else's gallery, search, tags, timeline and duplicate list — and a direct link to the file simply reports that there is nothing there.

Set it on one item in the viewer, on a selection in the gallery, or on a whole folder from the Visibility tab.

Folder decisions stick

A folder's setting is remembered as a rule, so photographs that land in it later inherit the decision instead of quietly reappearing at the default level. Rescanning never overwrites it.

There is an undo

Setting a rule on a folder rewrites everything beneath it, and the individual decisions it lands on would otherwise be lost. Ninaivu writes down the previous state first, and the Visibility tab offers an undo. If you ever choose the wrong button on the whole library, this is the button that saves you.

Chapter Sixteen

Sound recordings

Sound recordings are administrator-only. Not by default — as a rule. It does not depend on an item's visibility, no folder setting lifts it, and there is nothing in the family app that turns it on.

The reason is what actually ends up in a family's media folders. A library swept up from old drives and phone backups collects voice notes, voicemail, call recordings, dictation and meeting audio — things nobody chose to put in a gallery, and would never think to go and hide, because it never occurred to them they would be listed at all. A photograph is looked at on purpose. A sound file plays the moment somebody taps it, out loud, in a room with other people in it.

Photographs and video are unaffected. An existing library is put right the first time this version opens it.

Chapter Seventeen

Faces

Ninaivu can find the faces in your photographs and group them, so the gallery can be browsed by person. It all happens on your machine: no photograph, no face, and no measurement of a face is ever sent anywhere.

Switching it on

On Windows, start.bat already does. Otherwise add --faces when you start Ninaivu. Turning it on downloads nothing by itself — two small model files are fetched only when you press the button, and each is checked against a known fingerprint before it is used.

The first run

  1. Open the console and go to Faces.
  2. Press Download face models. About 37 megabytes, once, ever.
  3. Press Look for faces. Roughly twenty-five photographs a second. You can stop it and come back; it remembers where it got to.
  4. Groups appear under Groups waiting for a name. Type a name and press Enter.
  5. Use Review suggestions on a person to answer the faces it was unsure about, one click each.

How sure it has to be

Ninaivu is deliberately lopsided about which way it errs. Putting a stranger into somebody's album is expensive, because nobody ever goes looking for it. Failing to recognise somebody costs one click. So it only decides on its own when three things are all true: the face is a strong match for that person, it is clearly a better match for them than for anyone else in the library, and it resembles a face you yourself confirmed rather than just that person's average. Everything else becomes a question rather than an answer.

Only your answers teach it

A person is described by the faces you confirmed, never by the ones Ninaivu matched on its own. If its own guesses fed back in, one mistake would drag the description towards the wrong face and make the next mistake likelier — and an album would slowly fill with a stranger while every single step looked reasonable.

Saying “no” is permanent. Ninaivu never asks again, and never quietly assigns that face to somebody else instead.

Who can see it

A face can only ever be reached through its photograph, so every rule about who sees what applies to faces automatically. In particular, somebody who appears only in hidden photographs does not appear in the People list at all — not even with a nought beside their name, which would itself give away that they are somewhere in the library.

Two sensible expectations

  • Very small faces are skipped. Below about fifty pixels there is not enough detail to tell one person from another, and including them would produce one large group of blurry strangers.
  • Babies and young children change faster than any system can follow. Expect to name a child more than once as they grow, and merge the groups afterwards.

Chapter Eighteen

Deleting, and the recycle bin

Deleting from Ninaivu does not delete anything. The file is moved into a folder called _deleted at the top of its own library folder, and it is removed from the index only once the file has actually moved. Two deletions of the same filename both survive; the second gets a number added.

The bin is an ordinary folder. You can open it in Explorer or Finder and look, and you can restore from the console's Folders tab. Nothing expires on a timer — emptying it is your decision and nobody else's.

Chapter Nineteen

Sharing a photograph or an album

Family members and administrators can make a link to a single photograph or a whole album. Each link can carry an expiry date and a password, and Ninaivu counts how many times it has been opened so you can tell whether it was used. Links are listed on the console and can be revoked at any time, which takes effect immediately.

Albums themselves hold references, not copies. Deleting an album never touches a photograph.

Chapter Twenty

The Archive: old drives into one library

Most households do not have a library yet. They have four external drives, two old phone backups and a box of memory cards, with the same photograph on three of them. The Archive tab is the tool that turns that into something worth pointing the library at.

Give it your source folders and a destination, and it copies every photograph, video and sound file into one archive filed by the date it was taken:

MasterArchive/
  2016/02/03/IMG_0001.jpg
  2019/10/10/IMG_0042.jpg
  undated/CLIP.DAT

What it promises

  • Nothing is re-encoded. Files are copied byte for byte. A photograph that goes in comes out identical — same pixels, same camera information, same everything.
  • Nothing is deleted, ever. Your drives are opened read-only. Duplicates are written down and left exactly where they are.
  • Nothing is trusted unverified. Every file is fingerprinted as it is read, then the copy is read back off the destination disk and fingerprinted again. Only a match counts.
  • Nothing is left half-written. Copies land under a temporary name and are put into place only once complete. Pull the plug mid-run and the archive holds whole files or nothing.
  • Unplugging a drive is safe. If a drive disappears mid-file the partial copy is thrown away and the run waits. Plug the same drive back in and it carries on, stepping over everything already verified. A different drive in the same socket is refused.
  • Nothing is skipped silently. A file with a missing or wrong extension is identified by looking inside it, so a JPEG named .txt is still archived.
  • Start is also Resume. Stop it and press start again whenever you like.

There is also a guardian that periodically samples the archive, re-reads files and compares them against what was recorded, reporting anything missing, changed or unreadable. It also warns you when the destination drive drops below a tenth free.

Chapter Twenty-one

Cloud backup

The Cloud tab keeps a second copy of the library in one folder in a Google Drive account you choose. It is deliberately narrow:

  • One way. Files go out. Nothing is ever downloaded, changed or removed on this machine.
  • Once. Every file goes up exactly once, recorded against its path rather than an internal number — because numbers get reused, and a reused number inheriting somebody else's “already sent” is how a file goes missing without anyone noticing.
  • Deleting in Drive is not an instruction. Clear space up there and Ninaivu does not notice, does not send it again, and above all does not treat the absence as a request to delete anything here.
  • Hidden photographs stay here. Hiding something from your own household is not consent to put it on Google. There is a switch, and it is off.
  • Pausing is instant. Pausing a four-gigabyte video takes effect in seconds and costs nothing — it picks up where it stopped.

Uploads run one file at a time. Not because doing several would be hard, but because what is being shared is your home broadband: four at once do not finish sooner, they just stop the house using the internet.

Speed and hours

Two controls, both applied to the transfer already in progress rather than the next one. A speed limit in kilobytes per second, and the hours it may run — 22:00 to 07:00 crosses midnight as you would expect. An upload still going when the hours end stops where it is and carries on the next night; nothing already sent has to go again, and the file is recorded as still waiting rather than as a failure.

Setting it up

Ninaivu cannot ship a Google password of its own — one hidden inside a program anybody can unzip is not a secret, and a shared one would put every household behind a single quota. So you make your own once, in the Google Cloud console: create a project, switch on the Drive API, make an OAuth client of type Web application, and paste the two values the Cloud tab asks for. The tab shows you the exact redirect address to paste back, with a copy button.

Ninaivu asks for the narrowest permission Google offers: it can see and manage only the files it creates itself. It cannot read a single thing already in your Drive.

Worth knowing before the first run

The Drive client has been tested thoroughly against a stand-in that behaves like Google — including the awkward parts — but not yet against Google itself. That proves it implements the protocol correctly. It does not prove a real upload works. Watch the first one.

Part Four

Keeping it running

The network, padlocks, what to do when something looks wrong, and where everything lives.

Chapter Twenty-two

The machine, the network and sleep

Letting the rest of the house in

Ninaivu already listens on every address the machine has. The banner it prints on startup tells you what to type on the other devices:

  on your network:
    family  → http://192.168.1.24:5000   ← phones and tablets
    admin   → http://192.168.1.24:3000

Give the machine a fixed address in your router settings so that number never changes, and allow the port through the firewall the first time you are asked.

A name instead of a number

Nobody remembers 192.168.1.24. Ninaivu announces itself on the network, so most devices can simply use http://ninaivu.local:5000. Apple devices always understand this, Windows 10 and later do, most Linux desktops do, and Android is unreliable below version 12 — anything left out can still use the number.

The approach that always works is a name entry in the router itself, listed under something like DHCP reservation or Local DNS.

When other devices see nothing

Run this on the machine serving the library:

python tools/netcheck.py

It says whether Ninaivu is reachable beyond this machine, which of its addresses is the one on the family Wi-Fi (a machine with a VPN has several, and only one is right), and the exact firewall command for your system. In order of likelihood the cause is the firewall, a phone on the Guest network, or the router keeping devices apart from each other.

Reaching it from outside the house

Use a VPN into your home network. Never open a port on the router to the internet.

Sleep

Ninaivu keeps the machine awake while it is running, so a long scan or an overnight upload is not cut off half way. If you would rather it did not, add --allow-sleep.

Chapter Twenty-three

Padlocks: turning on HTTPS

Add --https and Ninaivu serves the house over an encrypted connection.

The complication is that no certificate authority on earth will vouch for a home address like 192.168.1.24, and a plain self-signed certificate greets everybody with a full-page security warning — which teaches the whole household to click through security warnings. So Ninaivu creates its own small authority, keeps the key on your machine, and signs a certificate with it. Install that authority once per device and every browser in the house shows an ordinary padlock.

DeviceWhat to do
iPhone, iPadOpen the certificate address in Safari, allow the download, then Settings → Profile Downloaded → Install. Then Settings → General → About → Certificate Trust Settings, and switch Ninaivu on.
AndroidOpen the same address, then Settings → Security → Encryption & credentials → Install a certificate → CA certificate.
WindowsDouble-click the file → Install Certificate → Local Machine → Trusted Root Certification Authorities.
macOSDouble-click, then in Keychain Access set it to Always Trust.

The certificate lasts 397 days — the longest Apple devices will accept — and Ninaivu renews it automatically before it runs out. Because the authority itself is unchanged, nothing needs installing a second time. Move the machine to a different network and the certificate is quietly reissued for the new address.

Chapter Twenty-four

When something goes wrong

Nothing loads on the other devices
Run python tools/netcheck.py on the server. Almost always the firewall, a Guest network, or the router isolating devices from each other.
It loads forever, then gives up
Usually a very large library still on its first walk. The banner shows progress, and the gallery becomes usable before the walk finishes.
Every photograph is in the same month
The extra date reader is missing, so Ninaivu is falling back to file timestamps. Installing exifread fixes it; a rescan then puts the dates right.
Some photographs are on their side
Press R in the viewer. One person fixing it fixes it for the whole household, and the file itself is never modified.
The Faces tab says it is unavailable
Either the models have not been downloaded yet, or the installed OpenCV is missing the face modules. The tab prints the precise reason.
Face grouping is missing people
Check the number still waiting to be looked at before assuming it is wrong. Remember that very small faces are skipped deliberately.
A guest can see more than expected
Use the console's What each role sees panel. It works the answer out exactly the way a real request does, rather than guessing.
Sound files will not play
Working as designed. Sound recordings are administrator-only and no setting changes that.
The library scrubber says everything is fine
It would. In this version it records each file's fingerprint but never compares it against the previous run, so it cannot detect a file that has silently changed — only one that has gone missing or cannot be read. The Archive tab's guardian does compare properly; rely on that one.
