    Library

    Uploads awaiting approval

    Family uploads stay private here until you approve them. Review the creation date; approval moves the file to its year/month/day folder and applies the family date visibility rules.

    Phone backups

    Family members can back up their phones from the family app (Back up this phone). Each photo arrives checked and is never stored twice. A backup waits here for approval like any upload, unless you trust phone backups; an administrator's own phone is always filed straight away.

    Profiles

    Admins manage the library. Family members view, download and keep their own favourites. Guests see public media only.

    Faces

    Ninaivu groups the faces in your photographs so you can browse by person. Everything runs on this machine — no photograph and no face ever leaves it. Grouping is deliberately cautious: it only decides on its own when it is certain, and asks you about everything else.

    People

    Named people. Family members see these too, but counted only across the photographs they are allowed to open.

    Groups waiting for a name

    Each of these is a set of faces Ninaivu believes is one person. Give one a name and it becomes a person straight away — and the next regroup will look for them across the whole library.

    Straighten

    Photographs arrive sideways when the app that last touched them threw away the camera's note about which way up they go. Ninaivu can find those and put them right — it only ever touches photographs with people in them, it never writes to your original files, and nothing changes until you say so.

    Ready to straighten

    Each one is shown the way Ninaivu would leave it. Click a photograph to skip it.

    Indexing

    Library folders

    Every folder Ninaivu indexes. Add as many as you like — each family member can be given one of them, or a folder inside one.

    Photos without a location

    A photograph taken close in time to one that has a location was very likely taken in the same place — often a second camera with no GPS on the same trip. Ninaivu can give it that place, so it shows on the map and in its places. Only Ninaivu's index changes, never your files, and every one can be taken back.

        Mugil — cloud backup

        one way · Google Drive

        A second copy of the library, kept in one folder in a Google Drive account you choose. It only ever goes out.

        What that means, exactly
        • Every file is uploaded once. The record of what has gone is kept here and is never cleared by anything Google does.
        • Deleting a photograph in Drive does not delete it here, and does not cause it to be uploaded again.
        • Uploading never changes or removes anything on this machine. Getting files back is a separate step, Restore from Google Drive below, and it never overwrites a file.
        • Ninaivu works inside one folder it makes itself. The rest of the Drive account is not read and not touched.
        • Hidden items stay here unless you say otherwise.

        Google account

        Not connected
        One-time setup in Google Cloud

        Ninaivu cannot ship a Google client secret — a secret inside an app anybody can unzip is not a secret, and a shared one would put every household behind one quota. It is about five minutes:

        1. Open console.cloud.google.com and make a project.
        2. Enable the Google Drive API for it.
        3. Under Credentials, create an OAuth client of type Web application.
        4. Add this exact authorised redirect URI: …
        5. Paste the client ID and secret below.

        Ninaivu asks for the narrowest permission Google offers — access to the files it creates itself, and nothing else in your Drive.

        Settings

        Everything in the library is backed up except hidden items — anything only admins can see — unless Hidden things, below, says they may go. Photos still waiting to be checked for screenshots and documents go up once they have been.

        Renaming makes a new folder. Anything already uploaded stays where it is — Ninaivu does not move things around in somebody's Drive.

        Encryption

        off

        Encrypt each file on this machine before it goes to Drive, so nobody who can see the Drive account — Google included — can see the photographs.

        Read this before making a key
        • The key is made from a passphrase you choose, and kept on this machine so uploads carry on after a restart.
        • You will get a recovery file. Keep it somewhere that is not this computer and not that Google account — a USB stick in a drawer, a password manager.
        • If this machine is lost, the recovery file, or the passphrase, decrypts the backups. Lose both and nobody can read them, Ninaivu included.
        • Files already uploaded stay as they are; only files uploaded after encryption is on are encrypted.

        Decrypt downloaded backups with python tools/cloud_decrypt.py --recovery ninaivu-recovery.json <downloaded folder> <output folder>.

        Speed and hours

        no limit · any time

        0 means no limit. A limit is for keeping the connection cheap, or for a line where the rest of the house notices. A new limit applies to an upload already running.

        Each file waits about two seconds on Google before any of it moves, so one at a time, a library of photographs uses a fraction of the line. Several at once overlap those waits. Applies from the next batch of files.

        Otherwise the backup makes way for the household as the workload mode says: in Quiet, it waits while anybody is using Ninaivu. Either way it waits while somebody uses Ninaivu from outside the house, since what they open comes up the same internet connection. Upload hours and a speed limit still apply.

        Leave both empty to upload at any hour. A start later than the end means overnight — 22:00 to 07:00. An upload still going when the hours end stops where it is and carries on the next night; nothing already sent has to go again.

        Drives

        What Windows has logged about each drive in the last week — bad blocks, failed writes, USB resets — and what Windows itself says about its health. Checked every ten minutes; a drive that looks like it is failing is also sent as a notification.

        Storage integrity

        Fingerprints every file with SHA-256 and compares it against the last run, so a photograph whose bytes decayed on disk is reported. The first run has nothing to compare against, so it records fingerprints rather than verifying them — run it twice to get an answer. A file you edited yourself is not corruption, and is not reported as such.

        Notifications

        A server that runs all year fails quietly. Ninaivu can send a line somewhere when something needs you — a file whose bytes changed, a backup that stopped, a drive that went away. Off until you fill one of these in, and it never sends what is in your photographs.

        Works with ntfy, Gotify, Discord, Slack and Home Assistant.

        A photograph, once a week

        Everything else here is about keeping your photographs. This is the one part that gives one back: on the morning you choose, Ninaivu picks the best photograph from that day in a past year and emails it to the family — the picture itself, in the message, not a link to come and find it.

        It chooses on what the scan already worked out: it prefers people, prefers older years, and refuses screenshots, blurred frames, videos, anything hidden, and the ninth near-identical shot of one moment. A day with nothing worth sending stays quiet, which is what keeps the ones that do arrive worth opening. Unlike the notifications above, this one does contain your photographs — that is the point of it.

        Fill in the email settings above first — this uses the same mail server, and there is nothing for it to send through yet.

        A home server is only reachable from the house, so this is left to you rather than guessed.

        Moving Ninaivu to another computer

        Three things make this installation. Copy them to the new machine and Ninaivu is the same there — the same albums, the same face groups, the same names on places, the same decisions about who can see what. None of that is in the photographs themselves.

        Walking a few hundred thousand thumbnails takes a moment, so it is only done when you ask.

        Copy with Ninaivu stopped. The index is written continuously while it runs, and a copy taken mid-write is a database that will not open on the other side.

        The library has moved

        Every photograph in the index records the folder it is in, and every thumbnail is named after it. So a drive that was E: here and comes up as D: there leaves an index pointing at nothing and every thumbnail orphaned — and the next scan reads that as an empty library.

        Pointing the index at the new folder takes minutes and keeps all of it. Letting it rescan takes most of a day and rebuilds what you already have.

        What this does not touch: face crops and converted copies are filed by item, not by path, so they follow the library wherever it goes. The Archive keeps its own record of where it copied things from, which is a separate question.

        AI models

        Optional models that run on this machine. None come with Ninaivu: each is downloaded here, once, from the source listed, and checked against a fixed checksum before it is used. Photographs never leave this machine for these tools.

        Restart Ninaivu to use the new search model

        SigLIP 2 is installed but search is still using the model it started with. After a restart the library is re-indexed for search in the background; search works again as each photo is processed.

        From a terminal instead: python tools/fetch_ai_models.py --get all

        Google Gemini

        Optional. Edits and descriptions done by Google's models rather than on this machine. Unlike everything above, a photograph you use with Gemini is sent to Google. Nothing is sent until somebody chooses a Gemini tool in the Playground, and only the photograph they chose.

        The key is checked with Google before it is kept, stored on this machine only, and never shown again — just its last four characters. Get one from Google AI Studio.

        AI server

        Off

        Run the Playground's heavy image edits on a ComfyUI server elsewhere in the house — a PC with a graphics card — instead of on this machine.

        What that means, exactly
        • When someone generates an edit or removes an object, a preview of that photo and their request are sent to the address below, and nowhere else. Ninaivu never follows a redirect elsewhere.
        • Nothing is sent until the server is switched on and a workflow is assigned to the job. Everything else stays on this machine.
        • Ninaivu's request filter still runs first. What the server's models will and will not produce is up to the workflow you choose.
        • ComfyUI has no sign-in. Keep it on your home network, and allow only this machine through that PC's firewall.
